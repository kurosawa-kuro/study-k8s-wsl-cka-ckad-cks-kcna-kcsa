| **CKAD v1.33** | **minikube (単一ノード)** addon で Ingress / dashboard も一発 | **kind 1 node × 反復** 秒で `delete`→`create`、手数を稼ぐ   | CRUD／Probe／ConfigMap など “アプリ寄り” が中心で **複数ノード要件なし**。UI addon 付き minikube で挙動を可視化→kind で指を慣らす。                                                       |
| **CKA v1.32**  | **kind マルチノード** `1CP+2W` を YAML 1 枚で即生成              | **ネイティブ kubeadm 3 ノード**（Multipass / Vagrant / 物理） | シラバス 25 % を占める **kubeadm** 操作（init／join／upgrade／etcd snapshot）が “手組み” 前提。kind で概念を掴み、最終週は **本物 kubeadm** をゼロから構築→破壊を繰り返して手順を身体に刻む。                 |
| **CKS v1.32**  | **minikube でも kind でも OK**                           | **kind ＋ APIserver フラグ／Gatekeeper／Falco**         | PodSecurityAdmission・auditLog・OPA など **APIServer 再起動やマニフェスト置換**が多い。kind の `kubeadmConfigPatches`／`extraMounts` で audit 設定を即反映できるため “試行回数を回す” のに最適。 |

> 🔸 **ポイント**
> 
> - **CKA だけは “素の kubeadm” を必ず体験**――etcd バックアップ／restore、証明書更新、ノードアップグレードを最低 2 周。
>     
> - **kind と kubeadm は両立**：kind で高速ループ → kubeadm で本番同等演習、の 2 段階が鉄板。
>     
> - WSL2 ＋ Docker なら minikube・kind はそのまま動く。kubeadm 検証は Hyper-V 上の Multipass／Vagrant VM を使うと楽。
>
