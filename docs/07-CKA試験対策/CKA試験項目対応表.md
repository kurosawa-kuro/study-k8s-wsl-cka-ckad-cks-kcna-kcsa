CKADおよびCKA対策表を、カテゴリ順の論理的なグルーピングや視認性を重視して、より見やすい構造へ整理いたします。  
カテゴリの並び順の統一、関連性の高いテーマの並列、表レイアウトの簡素化などを含めてリファクタリングを行います。  
完了次第、整形された新バージョンをご提案いたします。

## CKAD対策テーマ表 (v3)

|カテゴリ|項目|Ingress必要?|理由・出題傾向|
|---|---|---|---|
|🔰 **基本操作**|NamespaceとContextの切り替え|❌|試験では複数のコンテクストを扱うため、切替操作は必須の基本知識。|
|📦 **アプリケーション**|単一コンテナPod|❌|Kubernetesにおける最小のデプロイ単位で頻出。|
|📦 **アプリケーション**|複数コンテナPod（Initコンテナ/Sidecar）|❌|Initコンテナによる初期化処理やSidecarパターンの理解は必須。出題されることがある。|
|📦 **アプリケーション**|Deployment（ローリング更新/ロールバック）|❌|複数レプリカのアプリを管理しローリング更新を行う基本機能。ほぼ毎回出題される重要項目。|
|📦 **アプリケーション**|DaemonSet|❌|全ノードでPodを実行するためのコントローラ。出題頻度は高くないが、仕組みの理解は必要。|
|📦 **アプリケーション**|Job|❌|一時的なバッチ処理用リソース。出題されることもある。|
|📦 **アプリケーション**|CronJob|❌|定期実行のバッチ処理用リソースで、スケジュール設定ミスに注意。比較的頻出。|
|📦 **アプリケーション**|StatefulSet|❌|状態を持つアプリ用のコントローラで、PersistentVolumeClaimとセットで使用。出題されることがある。|
|⚙️ **構成**|ConfigMap|❌|設定情報を環境変数やボリュームとして提供する基本リソース。頻出。|
|⚙️ **構成**|Secret|❌|機密情報を扱う設定リソース。使い方はConfigMapと類似。頻出。|
|⚙️ **構成**|リソース要求/制限（requests/limits）|❌|コンテナのCPU/メモリ使用量を制御する設定。CKADでは頻出ではないが、理解しておく。|
|🌐 **ネットワーク**|Service（ClusterIP/NodePort）|❌|コンテナをネットワーク経由で公開する基本リソース。NodePortやClusterIPが頻出。|
|🌐 **ネットワーク**|Ingress|✅|外部からのHTTP(S)アクセスを集約し内部サービスへルーティングするリソース。ホスト名やパスに基づくルール設定がポイント。|
|💾 **ストレージ**|PersistentVolumeとPersistentVolumeClaim|❌|永続ボリュームを確保するための要求リソース（PVC）。Podにマウントして使用。出題頻度は高くない。|
|💾 **ストレージ**|ボリューム（emptyDir/hostPath）|❌|Pod内の一時データやノード上のデータを格納するボリューム。コンテナ間のデータ共有に利用。|
|🔍 **調査・復旧**|ログ確認（kubectl logs）|❌|コンテナの標準出力ログを確認し問題の原因を調査する基本手順。トラブルシュートで頻出。|
|🔍 **調査・復旧**|イベント確認（kubectl describe）|❌|リソースのイベントや状態を確認してエラー原因を特定。問題解決の手がかりになる。|
|🔍 **調査・復旧**|トラブルシュート手法（kubectl exec/debug）|❌|コンテナ内に入って調査・復旧する手法。kubectl execやデバッグ用コンテナ機能を活用する。|

| カテゴリ                   | 項目                               | Ingress必要? | 理由・出題傾向                                                                 |
| ---------------------- | -------------------------------- | ---------- | ----------------------------------------------------------------------- |
| 🏗️ **クラスタ構築・設定**      | etcdバックアップ/復元                    | ❌          | 致命的障害に備えてetcdデータをバックアップ/リストアする手順。頻出。                                    |
| 🏗️ **クラスタ構築・設定**      | クラスタアップグレード/ノード追加（kubeadm）       | ❌          | kubeadmによるクラスターのアップグレードやノード追加。頻度は高くないが出題可能。                             |
| 🏗️ **クラスタ構築・設定**      | 証明書と認証（TLS設定/ kubeconfig）        | ❌          | 証明書の期限切れ対応やkubeconfig設定など認証関連の問題対応。まれに出題。                               |
| 🏗️ **クラスタ構築・設定**      | ノードメンテナンス（cordon/drain）          | ❌          | ノードのスケジュール停止(cordon)や退役(drain)手順。頻出ではないが実運用で重要。                         |
| 📦 **ワークロード/スケジューリング** | Deployment管理（ローリング更新/rollback）   | ❌          | ローリング更新やロールバックの操作。CKAでも基本事項。                                            |
| 📦 **ワークロード/スケジューリング** | ノード選択（NodeSelector/アフィニティ）       | ❌          | Podを特定ノードに配置するための設定（ノードセレクタ/アフィニティ）。出題されることがある。                         |
| 📦 **ワークロード/スケジューリング** | TaintとToleration                 | ❌          | Taint（ノード側の制限）とToleration（Pod側の許可）による配置制御。マスターノードへのPod配置などで頻出。          |
| 📦 **ワークロード/スケジューリング** | リソース割当（ResourceQuota/LimitRange） | ❌          | ネームスペースのリソース使用量を制限する仕組み。複数ユーザ環境のために重要。たまに出題。                            |
| 📦 **ワークロード/スケジューリング** | バッチ処理ジョブ（Job/CronJob）            | ❌          | バッチ処理用リソース（単発のJob/定期実行のCronJob）。CKAでは頻度は高くないが出題可能。                      |
| 📦 **ワークロード/スケジューリング** | DaemonSet                        | ❌          | 全ノードでPodを実行するコントローラ。CKAでは頻度は低め。                                         |
| 🌐 **ネットワーク**          | Service                          | ❌          | Podへのアクセスを提供する基本ネットワークリソース。CKAでも知識必須だが、単独で問われることは稀。                     |
| 🌐 **ネットワーク**          | NetworkPolicy                    | ❌          | Pod間の通信を制限するネットワークポリシー。許可ルールの書き方を理解。頻出。                                 |
| 💾 **ストレージ**           | PersistentVolume/StorageClass    | ❌          | 永続ボリューム(PV)を手動作成しStorageClassで管理。PVCを介したボリューム供給の仕組みを理解。出題頻度は低め。         |
| 🔒 **セキュリティ**          | RBAC設定（Role/RoleBinding）         | ❌          | 操作権限を管理するRBAC設定。頻出。適切なリソース範囲とバインド先を理解。                                  |
| 🔒 **セキュリティ**          | ユーザ作成と認証（CSR）                    | ❌          | 新規ユーザ用証明書の発行（CSR生成と承認）およびkubeconfig追加。まれに出題される高度なトピック。                  |
| 🔍 **調査・復旧**           | Podがスケジューリングされない                 | ❌          | PodがPendingのまま動作しない原因を調査。リソース不足、Taint/ラベル不一致などを確認。頻出。                   |
| 🔍 **調査・復旧**           | Service経由でアクセスできない               | ❌          | Serviceを介した接続ができない場合の原因を調査。エンドポイント未設定やSelector誤り、NetworkPolicyの影響などを確認。 |
